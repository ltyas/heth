# مبيعاتك أسهل — Mubee3atak Ashal

تطبيق Android (Kotlin + Jetpack Compose + Material 3) لأصحاب محلات كروت الإنترنت في اليمن:
مخزون الكروت، المحافظ (جيب، جوالي، ون كاش، كاش يمن)، اكتشاف التحويلات، البيع وإرسال الكود عبر SMS، التقارير، النسخ الاحتياطي.

> **حالة المشروع:** الكود مكتوب بالكامل لكنه **لم يُبنَ ولم يُختبر على جهاز بعد** (بيئة الكتابة بلا Android SDK ولا شبكة).
> أول بناء قد يُظهر أخطاء بسيطة في الإصدارات أو الاستيرادات؛ أرسل نص الخطأ لإصلاحه.

## بناء ملف APK

### الطريقة 1: GitHub Actions (بدون تثبيت أي شيء)
1. أنشئ مستودعًا على GitHub وارفع محتويات هذا المجلد.
2. تبويب **Actions** ← **Build APK** ← **Run workflow** (أو يعمل تلقائيًا عند كل push).
3. حمّل الملف من **Artifacts** (`app-debug.apk`) وثبّته على الهاتف (فعّل «تثبيت من مصادر غير معروفة»).

### الطريقة 2: Android Studio
افتح المجلد بـ Android Studio (Koala أو أحدث) ثم Build ← Build APK(s).
أو من الطرفية بعد تثبيت Gradle 8.7 وJDK 17 وAndroid SDK 34:
```
gradle :app:assembleDebug
```
يظهر الملف في `app/build/outputs/apk/debug/`. (لتوليد Gradle Wrapper: `gradle wrapper --gradle-version 8.7`)

> النسخة الناتجة Debug موقّعة بمفتاح تطوير. للتوزيع الفعلي أنشئ مفتاح توقيع خاصًا بك وابنِ Release.

## البنية
```
app/src/main/java/ye/net/mubee3atak/
 ├─ data/    كيانات Room وDAOs وقاعدة البيانات وإعدادات DataStore
 ├─ logic/   TransferParser (قراءة الرسائل) · SalesEngine (البيع الذرّي) · Sms · Backup · Exporter
 ├─ system/  SmsReceiver · NotificationService · SmsStatusReceiver · SmsRetryWorker
 └─ ui/      شاشات Compose (رئيسية، كروت، مبيعات، محافظ، معلّقة، تقارير، سجلات، إعدادات، قفل) + MainViewModel
```
MVVM: الواجهات ← `MainViewModel` ← `SalesEngine`/DAOs (Room). المنطق المالي كله في `SalesEngine` داخل معاملات قاعدة بيانات.

## كيف يعمل البيع والتحقق (وحدوده بصراحة)
لا توجد واجهة برمجية رسمية موثّقة في هذا المشروع لأي من المحافظ الأربع، **ولم يُخترع أي تكامل**. التطبيق يكتشف التحويل من:
- **رسائل SMS** الواردة من المحفظة (صلاحية RECEIVE_SMS).
- **إشعارات** تطبيق المحفظة (خدمة قراءة الإشعارات).

وهذا مصدر **غير موثوق قطعيًا** (الرسائل قد تُزوَّر أو تتغير صيغتها). لذلك:
1. كل تحويل يُسجَّل أولًا كـ **معلّق** ولا يُسلَّم أي كرت.
2. **البيع التلقائي معطّل افتراضيًا** لكل محفظة. تفعّله من *المحافظ ← المحفظة ← إعدادات المحفظة* بعد أن تجرّب رسائلها الحقيقية في أداة «جرّب رسالة» وتتأكد أن المبلغ ورقم العملية ورقم العميل تُستخرج بدقة (يمكن تخصيص Regex لكل محفظة).
3. حتى مع التفعيل: لا بيع بدون **رقم عملية** و**رقم عميل** ومبلغ يطابق سعر كرت متاح؛ وإلا تبقى العملية للمراجعة اليدوية (شاشة *المزيد ← العمليات المعلّقة*).
4. للوصول لتحقق موثوق فعلًا تحتاج واجهة رسمية/اتفاقية مع شركة المحفظة (Webhook أو API لتجّار) ثم تُضاف كمصدر جديد يستدعي `SalesEngine.onIncoming` — الهيكل جاهز لذلك.

**قبل الاعتماد التجاري:** كلمات المرسل الافتراضية للمحافظ تخمينية؛ اضبطها حسب اسم المرسل/التطبيق الظاهر عندك، واختبر كل محفظة بمبالغ صغيرة.

## ضمانات الأمان والموثوقية المطبّقة
- منع تكرار التحويل: فهرس فريد `(المحفظة، رقم العملية)`؛ وبدون رقم عملية يُستخدم بصمة النص.
- منع بيع الكرت مرتين: `UPDATE ... WHERE status='AVAILABLE'` ذرّي داخل معاملة، وكود الكرت فريد.
- البيع كله (الكرت + سجل البيع + تأكيد التحويل + سجل الرسالة) في معاملة واحدة: انقطاع التطبيق لا يترك حالة نصف مكتملة.
- الرسائل: تُحجز ذريًا قبل الإرسال لمنع الإرسال المزدوج؛ الفاشلة تُعاد تلقائيًا حتى 3 مرات (WorkManager)؛ وما لم يصله تأكيد يُعلَّم «غير مؤكد» للمراجعة بدل إعادة إرساله آليًا.
- لا يوجد حذف للمبيعات أو الحركات المالية (لا يوجد DAO للحذف)؛ الحذف مسموح فقط لكروت «متاحة» لم تُبَع.
- سجل عمليات وأخطاء كامل، قفل PIN/بصمة، منع لقطات الشاشة (FLAG_SECURE)، `allowBackup=false`.
- النسخ الاحتياطي: ملف قاعدة البيانات مع تشفير اختياري AES-256-GCM (PBKDF2).
- **حدود:** قاعدة البيانات نفسها غير مشفّرة على الجهاز (محمية بعزل التطبيق). للتشفير الكامل يمكن لاحقًا استخدام SQLCipher.

## SMS وقيود Google Play
Google Play يقيّد صلاحيات SMS (`SEND_SMS`/`RECEIVE_SMS`) ولا يسمح بها إلا للتطبيقات التي هي معالج SMS الافتراضي أو ضمن استثناءات ضيقة، وغالبًا سيرفض هذا النوع من التطبيقات. الخيارات:
1. **التوزيع المباشر بملف APK** (الخيار العملي لهذا التطبيق). على أندرويد 13+ قد تحتاج: إعدادات التطبيق ← ⋮ ← «السماح بالإعدادات المقيّدة».
2. **التوزيع عبر متاجر بديلة** (مثل F-Droid أو متاجر محلية).
3. **للـ Play Store:** إزالة الإرسال المباشر واستبداله بفتح تطبيق الرسائل بنص جاهز (`Intent.ACTION_SENDTO`)، وإزالة قراءة SMS الوارد والاعتماد على قراءة الإشعارات/واجهة المحفظة الرسمية.

## ملاحظات
- العملة: ر.ي (YER) بلا كسور. الواجهة عربية RTL بالكامل، ودعم الوضع الليلي/النهاري.
- التصدير: CSV (يفتح في Excel) وPDF. لم يُضف تصدير xlsx أصلي لتجنّب مكتبات ثقيلة.
- استيراد CSV بالأعمدة: `الاسم,النوع,الكود,السعر,التكلفة,الصلاحية` (الصف الأول عنوان اختياري).
- لا توجد بيانات تجريبية؛ المحافظ الأربع تُنشأ فارغة عند أول تشغيل كإعدادات فقط.
- خطوات مقترحة لاحقًا: اختبارات وحدة لـ `TransferParser` و`SalesEngine`، تشفير DB، مصدر تحقق رسمي من المحفظة.
